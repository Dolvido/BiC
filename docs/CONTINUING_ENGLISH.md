# Continuing English learning in BiC

This experiment connects BiC's trainable English encoder, thirteen-region
recurrent brain, and reply decoder. English teaching and corrections enter the
student itself; regional activity continues between conversational turns.
Training updates neural weights, and interactive sessions can save and restore
their conversational state. The goal is to test these mechanisms in a small,
verified world, not to claim adult language understanding.

## Start, continue, inspect, and chat

Run these commands from the `brain-in-computer` directory using its Python
environment. On Windows, `.venv\Scripts\python.exe` can replace `python`.

```powershell
python -m brain_in_computer.dialogue_learning run --output local-results/english-01 --hours 0.25
python -m brain_in_computer.dialogue_learning status --output local-results/english-01
python -m brain_in_computer.dialogue_learning resume --output local-results/english-01 --hours 1
python -m brain_in_computer.dialogue_learning audit --output local-results/english-01
python -m brain_in_computer.dialogue_learning chat --output local-results/english-01
```

`run` needs an empty output directory and initializes an untrained student.
`resume` continues the saved configuration for additional wall-clock hours.
Source changes require a new experiment. A time limit can overrun while an
already-started update, evaluation, or save finishes. Ctrl+C preserves the last
completed learning cycle. `status` reads the saved progress report.

New runs accept `--seed`, `--steps`, `--device cpu` or `--device cuda`, and an
optional `--tutor-model INSTALLED_MODEL_NAME`. CPU is the default; GPU use
requires a compatible local PyTorch installation. These options do not change
the frozen configuration of an existing run.

The optional tutor contacts the local Ollama service to select one of two
verified dialogue lessons within the chosen topic. It does not download a
model, invent labels, or answer for the student during chat or audit. Invalid
or unavailable selections fall back to the procedural lesson selector.

A recorded live tutor probe (archive reference: `../runs/dialogue-tutor-probe/report.json`) verifies
that an installed local model can select a canonical English revision lesson.
It is connection and lesson-verification evidence, not a student-learning result.

## What English reaches

The input pipeline is UTF-8 bytes → learned byte embeddings and recurrent
utterance encoder → learned interface → recurrent BiC brain. A trainable byte
decoder produces replies from the brain's activity. There is no
pretrained LLM inside this student and no symbolic oracle at inference time.

The byte encoder and decoder restart for each utterance; the brain's regional
state persists between turns. This is continuing conversation at the utterance
level, not uninterrupted token-by-token language processing. Input utterances
are limited to 128 UTF-8 bytes; output generation is limited to 32 bytes.

All numeric observations are zero, including the task token and feedback. Alias
definitions and borrowing rules are available only through English. This makes
the experiment a controlled test of text and context dependence. It does not
yet integrate learned visual perception into these conversations.

Training samples whole independent six-turn conversations in parallel. Each
conversation carries its own state through all six turns, and gradients update
the language pathways and the brain together. Statements and questions provide
supervision for just four decision labels:

| Decision | Canonical training reply | Meaning in this world |
|---|---|---|
| Deny | `No.` | The known tool does not meet the current borrowing rule. |
| Allow | `Yes.` | The known tool meets the current borrowing rule. |
| Ask | `I need more information.` | Its meaning or the rule has not been provided. |
| Acknowledge | `Understood.` | A definition or rule has been presented. |

The displayed decision comes from the action head; the displayed reply is
generated by the byte decoder. A correct decision does not guarantee a correct
sentence. Neither output is replaced with the oracle's answer during chat.

## Curriculum and autonomous practice

Grounding binds an unfamiliar tool name to a color and applies an English rule.
Revision changes the rule and repeats the same question. Uncertainty introduces
questions before a required definition or rule, or asks about an undefined name.
The simulated tools are inert objects; no real borrowing or other external
action occurs.

The controller starts with grounding, then selects among the three topics using
development weaknesses and time since practice. This topic-selection policy is
engineered. It generates fresh verified dialogues and rehearses other topics
from compact seed descriptors. Two learning-rate branches explore alternative
updates; CPU branches may run concurrently, while GPU branches run serially.
An unpromoted exploration branch may continue learning without replacing the
accepted student.

Promotion uses development query performance and loss, with fixed retention
anchors for demonstrated topics. Oracle rules, labels, evaluation, and source
code stay fixed. The system cannot install arbitrary generated tasks or rewrite
its objectives. This restricts evolution to reviewed learning strategies.

## Try a continuing conversation

After opening `chat`, send one line at a time using the reviewed wording:

```text
A dax is the red tool.
Only red tools may be borrowed.
May I borrow the dax?
Now only blue tools may be borrowed.
May I borrow the dax?
May I borrow the wug?
```

These sentences ask the student to bind a name, allow borrowing, revise the
decision after a correction, and request missing information for an undefined
name. They illustrate the intended task; the checkpoint's measured ability
determines whether its replies are correct. Other supported colors are green,
blue, and yellow. Start with these short phrases rather than assuming arbitrary
English is understood.

Use `/reset` to clear conversation activity and `/quit` to save and exit. Chat
automatically saves after each ordinary turn and when it exits, normally to
`conversation.pt` inside the run directory. Reopening chat restores that state.
`--session PATH` selects another session file; its parent directory must exist.

Training changes weights; chat changes conversational activity only. A saved
session contains its weights and activity and is bound to that exact checkpoint.
If further training promotes different weights, chat rejects the old session;
choose a new `--session` path. Persisting a conversation is therefore distinct
from showing that its new facts were consolidated into neural weights.

## Read the evidence carefully

The audit uses withheld alias/color bindings and distinct sentence families.
All aliases and colors exist in training, but their held-out bindings do not.
This tests new compositions and wording, not wholly unseen words. Audit results
are saved separately and never enter topic selection or promotion.

All-turn accuracy includes easy acknowledgements. Query accuracy excludes
acknowledgements, but it still mixes decisions with requests for information.
Inspect per-topic, per-query-kind, and per-target metrics as well.

Counterfactual pairs share identical questions, ordering, and numeric inputs;
only an earlier English rule changes, requiring opposite allow/deny answers.
A constant allow or deny prediction scores 50% on those balanced individual
decisions and **zero** on the metric requiring both answers in a pair to be
correct. The report counts complete pairs; unpaired boundary episodes do not
contribute to that metric. Prediction flips alone do not establish correctness.

The same audit also resets state between turns or blanks all English. These
controls test whether performance depends on preceding context and text while
keeping the learned weights fixed. Compare their query and paired scores with
the intact student and the untrained baseline. Separately inspect exact reply
accuracy from free byte generation; teacher-forced reply loss is not equivalent
to producing a correct response independently.

## Scope and files

The existing visual `ComputerBrain` now exposes `forward_with_state` for
training and `respond_with_state` for inference across screen/text episodes.
These APIs preserve existing checkpoint parameter names and shapes. Callers
pass explicit regional state and only new frames; replaying old frames would
advance them twice. Batch rows must continue to represent the same sessions.
Activity can be saved through `brain.state_to_dict` with its matching weights.
This provides a compatible path toward continuing visual-language interaction.

The released visual checkpoint has not been jointly trained in this dialogue
experiment. The original symbolic curriculum loop remains complementary, with
a separate student. These paths do not yet form one unified learned checkpoint.
The four-label dialogue world also does not establish unrestricted English,
adult understanding, general planning, or permanent acquisition of new concepts.

`latest.pt` preserves accepted weights, optimizer and exploration state, and the
controller. `initial.pt` preserves the untrained baseline; `status.json` and
`protocol.json` record progress and configuration. Rehearsal descriptors and
recent history are bounded. Interactive `conversation.pt` is a separate artifact.

The relevant modules are `dialogue_curriculum.py` for exact lessons,
`dialogue_student.py` and `language.py` for neural learning and session state,
`dialogue_tutor.py` for external lesson selection, and `dialogue_learning.py` for
the persistent training loop and commands. Measured results should be reported
separately from this guide, including failures of contextual reasoning.
