# Learning from feedback: local lab

This experimental lab gives BiC a continuing stream of choices and consequences.
One of four object categories earns a reward. The rule changes during the episode
without telling the agent. Objects move between cells. BiC can use the previous
choice, its outcome, and its own neural working memory to decide what to try next.

Open **Start-BiC-Learning.cmd** in the workspace folder. The ordinary
**Start-BiC.cmd** still opens the existing computer and teaching labs.

In the learning lab, use **Step once** to inspect individual choices or **Run episode**
to watch the sequence. Save a session, take more steps, then reload it to return
to the saved point. Closing the window does not automatically save later steps.
A saved session includes the world and neural working state. Loading it requires
the same model and configuration. Start a new session for a new hidden rule.

## What is learning here?

Before deployment, the neural agent is trained on examples of a simple strategy:
use success and failure to narrow the possible rewarded categories. The examples
are generated by a scripted teacher using only observable feedback. It never
tells the neural agent the hidden rule. During the lab, model weights are fixed;
the agent adapts through its recurrent activity and memory. No tutor or network
service is contacted, and no real computer controls are operated.

The object categories are already identified for the agent. A small explicit
lookup translates its chosen category into the corresponding visible cell.
Therefore this experiment measures feedback-based adaptation, not learning to see,
spatial reasoning, English comprehension, or discovering entirely new concepts.
Its small new checkpoint is separate from the original desktop/language model.

## Commands

From the `brain-in-computer` folder, using the local Python environment:

```powershell
.\.venv\Scripts\python.exe -m brain_in_computer.adaptation_ui --checkpoint runs/adaptation-v07/selected-bic.pt --open-browser
```

The server uses `127.0.0.1:8767`; Ctrl+C in its terminal stops it. The launcher
uses the checkpoint selected from development results, before final evaluation.

To reproduce the fixed five-seed comparison in a **new** directory:

```powershell
.\.venv\Scripts\python.exe -m experiments.learn_adaptation --output runs/my-adaptation
```

For an implementation smoke run that cannot open the final test:

```powershell
.\.venv\Scripts\python.exe -m experiments.learn_adaptation --output runs/my-adaptation-smoke --development-only --seeds 11 --updates 100 --check-every 50
```

The default uses one CPU thread. On this small model, using the available GPU
is not a prerequisite. All generated results and checkpoints go under the new
output directory. Existing directories are rejected to protect prior evidence.
The protocol, exact sources, data hashes, development curves, selected checkpoints,
final trajectories, control comparisons, and restart checks are retained.

See [the prospective protocol](ADAPTATION_PROTOCOL.md) for budgets, metrics,
the comparison GRU, and the limits of the experiment.

## Research direction after this milestone

1. Test memory when the previous outcome is no longer immediately visible and
   when changes recur unpredictably; use new evaluation partitions.
2. Test whether retained episodes can teach a shared model without erasing its
   existing skills. Measure consolidation separately from saved recurrent state.
3. Learn action-conditioned predictions and test whether they improve planning.
4. Add opportunities to inspect or ask, and measure whether they reduce costly
   mistakes or unnecessary questions.

Progress is measured by acquisition speed, recovery, retention, transfer, and
useful information seeking. Keep the modular architecture only where comparisons
show it helps. The larger tutor/paraphrase study is deferred while these learning
mechanisms are established.
