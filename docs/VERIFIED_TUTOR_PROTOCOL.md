# External authored teaching and independent continuation

This prospective integration study extends the completed order-only tutor loop.
The external local LLM proposes compact chapter constraints. The canonical
compiler independently constructs and checks the English examples and answers.
The native learner receives these examples through its existing byte inputs and
unchanged learning objective. Teacher text, oracle states and answers never enter
unaided policy evaluation. This remains a finite English grammar experiment.

Before learner execution, two explicit preparation corrections were recorded:
[author transport recovery](VERIFIED_TUTOR_RECOVERY.md) preserved the first
HTTP400 attempt and used one separate compatible request; [collision recovery](VERIFIED_TUTOR_COMPILATION_RECOVERY.md)
preserved an incomplete compilation and added bounded deterministic resampling
inside the selected transformation. The accepted recipe is unchanged. All
attempts remain in the cost record, and neither correction used learner outcomes.

## Author and compiler boundary

Make at most one local chat request in the declared decision slot using the
installed pinned ministral-3:3b model. Persist intent before service activity,
keep exact returned response bytes, validate model identity before/after,
unload with keep_alive=0 and report actual teacher time and token usage.
An uncertain request is not automatically replayed. An invalid completed answer
can use only the declared procedural fallback, with its rejection recorded.
Withdrawal and persisted-result reuse make zero service calls.

The response contains only the bounded chapter recipe. It supplies no answers,
explanations, family allocations, code or withdrawal decisions. The teacher sees
only aggregate development counts and the compact chapter menu. The compiler
checks canonical regeneration, typed and English truth, opposite-answer pairs,
known and unknown queries, train-partition admission, exact protected transcript
exclusion, all-family/depth/length coverage and resource limits. Replay is prior
admitted training, never development or audit material. Compile and cache once;
GPU updates read authenticated example images without repeating author requests
or constructing the historical transcript inventory.

Report whether the accepted recipe and materialized inventory actually differ
from the procedural condition. Identical compiled examples constitute zero
treatment contrast, even if the recipe wording differs. Do not request another
recipe simply because the first agrees with the default or scores poorly.

## Native evaluation and restart

Use three explicitly reused banks from the completed continuation overlay:
development 720, actual original training-fit 108 and retention 720 episodes.
These banks have been observed in prior development; this is not a pristine
confirmation test. Freeze their bytes before either branch learns and score
both learners at relative updates 0, 108, 216. Retain all 18 bank endpoints and 9,288
raw episode records. Use native actions and freely generated replies from BOS.
Baseline scores must match between the identical restored branches.

After teaching, save both full continuation snapshots with the curriculum and
author identities; commit the phase only after both saved checkpoints and scores
exist. Release both learners and restore their complete snapshots for withdrawal.
The withdrawal worker makes no network calls. Save both final snapshots and
the final phase commit. There are four restorations and four saved checkpoints.

At each post-training endpoint, report procedural versus tutor with the existing
shared_state_screen.compare unchanged, explicitly labeling the reused development
bank despite the historical comparator's fresh_joint_gain key. Report each arm's
baseline-to-final acquisition separately. Report every family's known, unknown
and nonanchor actions and replies, opposite-answer joint success and retention.
For withdrawal also compare each arm's108-to-216 known/unknown slices on each
bank, with a five-percentage-point nonregression margin. A final tutor benefit
requires a nonzero example contrast, a passed final comparative screen, and
passed withdrawal nonregression; it remains single-parent exploratory evidence.
Failure or zero contrast cannot be presented as a teaching benefit.

## Cost and limits

The GPU worker has an 1,800-second inclusive allowance. Compilation and the one
author request are recorded separately, with all attempts and partial failures.
The worker decodes one enclosing parent checkpoint, then the exact continuation
wrapper decodes the two starting snapshots and two withdrawal snapshots. Report
these five checkpoint deserializations separately from lesson/bank archive reads.
Intermediate snapshot serialization is actual work even though it is in memory.
Report training, packing, target construction, evaluation, publication, source
checks, CPU time and peak GPU memory without adding nested costs twice.

There is no automatic retry, score-selected earlier endpoint, extra teacher call,
checkpoint promotion or changed acceptance rule. The broader objective remains
useful independent learning, retention and transfer beyond this small grammar.
