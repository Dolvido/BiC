architecture comparison is scored. No adviser is implemented or evaluated by

The next compatible decision boundary is the end of a completed cycle:

```text
advise(completed parent, lifetime retention, prior decisions,
       measured total cost, remaining allowance) -> stop | profile ID
```

Choose from a small, frozen catalogue of complete balanced curriculum profiles,
initially a short cycle and a standard cycle. Each preserves all three domains,
every declared depth and a rehearsal floor. Set exact profile sizes and decision
rules before the adviser comparison, after the architecture results inform the
learner contract. Use the same rule across subjects. Individual family/depth
results constrain regressions; they do not spawn bespoke repair tasks.

The existing English progress allocator cannot be connected directly. Its
`RealizationBackend` can repeat selected families, whereas every admitted
foundation bundle consumes one microbatch from each of three families under a
fixed schedule and a single optimizer update. Reusing the English allocator's
schedules would change the foundation learning contract. Its detached decision
records, cost accounting and coverage constraints are useful design references.

Persist the adviser's exact development evidence, retention snapshot, profile
catalogue, decision, allowance and lesson-seed position with the owner. Evaluate
only at declared boundaries, admit the entire chosen plan before learning, and
preserve cumulative exclusions. Stop or continuation decisions must survive
restart without double charging or repeating a completed decision. Source and
policy changes require an explicit new contract; old checkpoints are not
silently relabelled. An engineered adviser is not a learned scheduling policy.

## First measured-benefit comparison

Compare adviser-controlled continuation with fixed balanced continuation from
the same explicitly admitted research parent. Keep architecture, optimizer
state, seed stream, maximum budget and evaluation cadence matched. Freeze the
catalogue, decision thresholds, controls and all protected evaluation transcripts
before either arm begins. Use broad development evidence for decisions and
reserve the audit for the completed comparison.

The primary question is whether the adviser preserves teacher-free paired
action **and** reply accuracy on fresh compositions across all three domains
with fewer actual exposures and less total elapsed work. Report unsupported
answers, lifetime retention, every family/depth and matched-exposure checkpoints
alongside budget endpoints. Admission, validation, scoring, discarded work and
teacher cost count toward resource use. A shorter run alone is not success.
Begin with one paired screen; repeat only a promising result across independent
initializations before capability claims. Fresh syntax in these finite worlds
does not establish learning a new algorithm or broad English competence.

## External teaching and beneficial evolution

Add the external local tutor later as a separate comparison. It may propose a
catalogue choice using the same development evidence; independent validation,
coverage constraints and a procedural fallback remain authoritative. Record
requests, accepted proposals, failures and teacher cost. Declining request count
must accompany successful tutor-free acquisition of new skills; disabling a
teacher alone does not demonstrate independence.

Candidate changes must be judged by accurate answers, useful abstention,
retention and resource benefit under fixed evaluation rules. Increasing model
size, training time or a single score is insufficient. The current inert worlds
and fixed oracles bound these tests; they do not establish subjective welfare or
general ethical competence. Parallel work should first accelerate deterministic
preparation while preserving lesson order and one optimizer owner. Isolated
learning candidates need measured benefit per wall-clock budget before expansion.

## Current tutor integration boundary

The original local Ministral probe accepted two verified practice selections
and all eight returned examples passed the independent verifier. It performed
no student training. The subsequent complete local pilot now joins an actual
LLM decision to learner updates, unaided evaluation, full optimizer continuation
and teacher withdrawal. See [the completed results](FOUNDATION_TUTOR_LOOP_RESULTS.md).

The persisted decision adapter makes one local
request at a completed-cycle boundary, using development learning/retention
counts and a fixed catalogue of whole balanced curricula. Persist the request
intent before contacting the tutor and the validated choice before beginning
learning. Reopening a completed decision reuses it; an unfinished request is
reported as uncertain work and never silently replayed. The response can select
a catalogue entry, not invent labels, executable code or new evaluation facts.
Rejected responses retain their cost and use an explicit recorded procedural
choice when the request's outcome is known.

The adapter is now implemented in `experiments/foundation_tutor_adviser.py`.
Seven mock tests passed across eight persisted decision slots, including a
Windows path longer than 300 characters, saved-response verification, accepted
choice reuse, rejected choices, interrupted requests, source changes and
caller-controlled withdrawal. The run made 23 simulated API calls and zero
real network calls, lesson generations, learner updates or GPU operations.
The validation receipt (archive reference: `../runs/foundation-tutor-adviser-validation-local/attempt-001/report.json`)
records its exact scope. The complete pilot subsequently made one live accepted
request through this adapter, with no repeat during recovery.

The explicit continuation bridge now preserves the layout trainer's weights,
full AdamW state and evidence across fresh processes. Both GPU restart routes
succeeded in the pilot after a targeted JSON metadata-format repair. Original
checkpoint identities were preserved; no checkpoint was relabelled as an older
provider. The separate new pilot runner executes this integration rather than
silently changing the old cycle owner's contract.

The completed pilot retained 648 updates and 62,208 training episode exposures.
Its final 216-update cycle used fresh material and zero tutor API calls. Final
audit performance remained weak: no changed-fact pair had both correct actions
and exact English replies in both versions (0/396). The tutor selected the same
order as the procedural default, and no matched benefit comparison was run.

The next comparison must test useful teaching against equal-budget procedural
continuation and evaluate new acquisition, retention and unaided transfer.
Reducing request count without those outcomes does not establish progressive
independence. Shared factual reasoning and action/reply consistency need work
across the curriculum; connecting the teacher is no longer a pending prerequisite.
