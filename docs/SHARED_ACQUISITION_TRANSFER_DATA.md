# Finite compositional and query-placement transfer banks

This additive preparation supports the longer shared acquisition study. It uses
seed `852902001`, six counterfactual parent pairs per family/depth/turn cell,
and a single 900-second CPU invocation. It permits at most 12,000 counted calls
to the canonical pair generator, including all validator reconstruction copies,
and 64 candidate attempts per requested pair. Exhaustion preserves a failed
receipt; it never changes a split or weakens an exclusion. No model, optimizer,
GPU, teacher request or state-head prediction occurs during preparation.

The fixed banks are:

| Bank | Episodes | Canonical scope | Layout |
|---|---:|---|---|
| dev | 648 | All three families, depths 0–5, lengths 8/10/12; train structures | original |
| transfer_original | 432 | All three families, audit structures at depths 2–5, lengths 8/10/12 | original |
| transfer_varied | 432 | The exact same transfer parents and query answers | varied legal placement |
| train_fit | 108 | Reused actual original training examples | original |
| retention | 720 | Reused previously observed development examples | original |

There are 2,340 episode records per complete evaluation. The new dev bank has
fresh observed text but is not asserted to preserve an exact practiced program.
Depth-zero and depth-one primitives are shared; they are not structural
holdouts. Depth two has train copy→advance and audit advance→copy, with no dev
partition. Depth three through five retain the existing syntactic query-ancestry
partitions. Audit-partition compositions are withheld from the current
train-partition learning streams. These partitions have been studied before and
do not mean unseen algorithms, new English, or globally unobserved concepts.

Both transfer views are scored at the baseline and declared cycle endpoints.
They are repeatedly observed diagnostic transfer banks, not a pristine final
audit. Their mechanical evaluator role is `audit` because that role permits the
existing audit-partition structures. Native actions and freely generated English
replies remain the evaluation outputs; no teacher, parser or oracle answer is
provided to policy inference.

The existing layout adapter preserves the exact full event and byte multiset,
relative statement order, every query's immutable write-version ancestry and
truth in both counterfactual members. The explicit known anchor need not be last.
The legal terminal policies are anchor-last and unknown-last, plus statement-last
only where feasible. Deep/short chains can lack the last option. A deterministic
varied draw can equal the original; the receipt reports actual changed pairs,
nonterminal anchors and terminal-policy support. It does not force impossible
quotas or claim every example moved.

Fresh dev and both transfer views exclude the exact union of the authenticated
1,641,672 historical/reserved/four-development transcript inventory, the 62,208
original admitted training transcripts, and every transcript from the completed
procedural teaching, tutor teaching and common withdrawal streams (324 distinct
archive images). This excludes both branches, even though the next learner has
only one branch as its parent. The 108 fitting and 720 retained evaluation rows
are deliberate, labeled reuse and are not described as freshly excluded rows.

New pairs and their two transfer views are admitted atomically. Exact text may
overlap between views only for the same canonical parent and member; overlap
with another pair or the exclusion inventory causes a bounded deterministic
candidate retry. Procedure/naming/value seeds and layout seed omit the family
label. Failed family-specific candidates can lead to different accepted attempts,
which provenance records. No scores, target values or rendered names select the
layout. All current generator and causal-layout validators remain unchanged.

The manifest pins the input archives, source copies, complete banks and compact
parent recipes. It records exact exclusion counts/digests, semantic partitions,
cell counts, placement exposure and every rejection category. Work records count
actual generator calls and returned row copies, not unique learned episodes.
CPU guards prevent model construction, forward/backward, optimization and CUDA.
